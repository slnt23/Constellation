# Kite 前端开发规范

## 1. 架构模型

Kite 采用 **Hybrid（按业务 + 公共层）** 架构：

- `src/core/`：框架级能力，与业务无关。包括 API 请求层、路由、权限、配置、自动生成类型声明。
- `src/shared/`：被两个及以上业务模块复用的代码。包括共享组件、常量、类型、样式和静态资源。
- `src/modules/<feature>/`：业务模块。页面、组件、API、store、composables、常量、类型都收在模块内。
- `src/layouts/`：门户布局骨架。

不再使用旧的全局限层目录（`views/`、`components/`、`stores/`、`composables/`、`api/`、`types/`、`constant/`、`config/`、`router/`、`utils/`）。

## 2. 业务模块结构

每个业务模块内部保持统一：

```text
src/modules/blog/
├── pages/
├── components/
├── api/
├── store/
├── composables/
├── constants/
├── types/
├── services/
└── index.ts
```

模块 `index.ts` 是模块对外入口，导出页面、API、类型、常量和 composable。

## 3. 强制边界

- 新增业务代码只能放在 `src/modules/<feature>/` 下。
- `src/core/` 只放框架级能力：Axios、Router、Permission、Plugin、Config。
- `src/shared/` 只放至少被两个业务模块复用的代码。
- 不允许再新增全局 `views/`、`components/`、`api/`、`types/`、`constants/` 等按层目录。
- 页面负责展示与协调；业务逻辑进入 `composables/`、`services/` 或 `store/`；网络请求进入 `api/`。

## 4. 页面与逻辑分层

页面禁止堆积大量业务代码：

```text
modules/blog/pages/BlogDetail.vue        # 只做展示与协调
modules/blog/composables/useBlogDetail.ts # 数据、watch、API 调用
```

页面 setup 中只保留：

- 调用 composable / store
- 路由与组件组合
- 模板所需的少量派生状态

## 5. 数据流

```text
modules/<feature>/pages + components
        ↓
modules/<feature>/composables + store
        ↓
modules/<feature>/api
        ↓
src/core/api/request
        ↓
后端接口
```

## 6. 命名规范

- 页面：`HomePage.vue`、`PostsPage.vue`、`UserProfilePage.vue`
- 组件：`BlogCard.vue`、`PriceTrend.vue`
- Composable：`useBlogDetail.ts`、`useUserProfile.ts`
- Store：`article.store.ts`、`priceItem.store.ts`
- API：按资源命名 `article.ts`、`comment.ts`
- 类型：按资源命名 `article.ts`、`dto.ts`、`vo.ts`

统一使用 `@/` 别名，优先从模块 `index.ts` 导入。

## 7. 目录深度与宽度

- 目录深度控制在 4～6 层以内，超过则重新拆分。
- 同一级目录下的子目录或文件数量尽量不超过 15～20 个。
- 深度不是问题，横向跳转距离才是问题：开发一个功能时尽量只在对应模块内完成。

## 8. 类型与常量

- 业务类型放在 `modules/<feature>/types/`。
- 跨模块共享类型放在 `src/shared/types/`。
- 业务常量放在 `modules/<feature>/constants/`。
- 全局共享常量放在 `src/shared/constants/`。
- 禁止用本地示例/mock 数据冒充接口返回，禁止保留注释中的 mock 数据块。

## 9. 样式

- SCSS 保持 scoped 和 BEM 风格。
- 使用 `src/shared/styles/_tokens.scss` 设计令牌，禁止硬编码颜色。
- 全局样式统一由共享样式入口引入。

## 10. 验证

```bash
npm run type-check   # 提交前主验证
npm run build        # 涉及构建配置或新增依赖时执行
```

当前项目没有 ESLint / 测试脚本，后续引入时按仓库约定补到 `package.json`。
