# Kite 项目架构说明

## 1. 项目概述

Kite 是一个基于 **Vue 3 + TypeScript + Vite** 构建的现代化全栈前端应用，采用 **Hybrid（按业务模块 + 公共层）** 架构，涵盖前台门户、管理后台、AI 对话、价格查询、冥想等多个业务领域。

### 技术栈

| 类别       | 技术                                         |
| ---------- | -------------------------------------------- |
| 框架       | Vue 3.5（Composition API）                   |
| 语言       | TypeScript 6.0                               |
| 构建工具   | Vite 7.3                                    |
| 路由       | Vue Router 5.0                               |
| 状态管理   | Pinia 3.0                                    |
| UI 组件库  | Element Plus 2.13                            |
| HTTP 客户端 | Axios 1.15                                  |
| 图表       | ECharts 6.0 + vue-echarts 8.0                |
| Markdown   | marked 18.0                                  |
| 样式       | SCSS（Sass 1.99）                            |
| 代码检查   | vue-tsc（类型检查）                          |

## 3. 核心架构：三层模型

Kite 采用清晰的三层架构，确保关注点分离和代码可维护性：

```text
┌─────────────────────────────────────────────────────┐
│                    src/modules/                      │
│        （业务模块：页面、组件、API、Store、逻辑）        │
│    ┌──────────┐ ┌──────────┐ ┌──────────────────┐   │
│    │   home   │ │   blog   │ │  price / admin   │   │
│    │          │ │          │ │  / ai / story ... │   │
│    └──────────┘ └──────────┘ └──────────────────┘   │
├─────────────────────────────────────────────────────┤
│                    src/shared/                       │
│     （跨模块共享：组件、常量、类型、样式、工具函数）      │
├─────────────────────────────────────────────────────┤
│                     src/core/                        │
│     （框架级能力：API 请求层、路由、权限、配置）         │
└─────────────────────────────────────────────────────┘
```

### 3.1 `src/core/` — 框架级能力

与业务无关的底层基础设施，类比"操作系统内核"。

```text
src/core/
├── api/
│   ├── axios.ts              # Axios 实例创建
│   ├── interceptor.ts        # 请求/响应拦截器
│   └── request.ts            # 统一导出入口
├── config/
│   ├── app.config.ts         # 应用全局配置
│   ├── env.d.ts              # 环境变量类型声明
│   ├── modules.ts            # 模块配置聚合
│   └── modules/              # 按门户拆分的配置模块
│       ├── admin/            # 管理后台配置
│       └── front/            # 前台门户配置
├── permission/
│   ├── auth.ts               # 认证状态管理
│   └── index.ts              # 权限导出入口
└── router/
    ├── index.ts              # 路由实例 + 全局守卫
    └── modules/              # 按门户拆分的路由模块
        ├── admin.routes.ts   # 管理后台路由
        └── front.routes.ts   # 前台门户路由
```

**职责边界**：
- 只放框架级能力：Axios、Router、Permission、Config
- 不允许放业务代码、UI 组件、业务常量或类型

### 3.2 `src/shared/` — 跨模块共享

被 **两个及以上** 业务模块复用的代码。

```text
src/shared/
├── assets/                   # 静态资源
│   ├── gallery/              # 图片素材
│   ├── home/                 # 首页资源
│   ├── icons/                # 图标
│   ├── login/                # 登录页资源
│   ├── logos/                # Logo 资源
│   ├── status/               # 状态占位图
│   └── ui/                   # UI 通用素材
├── components/               # 共享组件
│   ├── LoginDialog.vue       # 登录弹窗
│   ├── MenuPanel.vue         # 菜单面板
│   └── SiteFooter.vue        # 站点页脚
├── constants/                # 全局共享常量
│   ├── key.ts                # 键名常量
│   ├── navigation.ts         # 导航配置
│   └── user.ts               # 用户相关常量
├── styles/                   # 全局样式
│   ├── themes/               # 主题样式
│   ├── _base.scss            # 基础样式
│   ├── _element-plus.scss    # Element Plus 覆盖
│   ├── _tokens.scss          # 设计令牌
│   ├── _utilities.scss       # 工具类
│   └── index.scss            # 样式入口
├── theme/                    # 主题系统
│   ├── index.ts              # 主题初始化
│   ├── registry.ts           # 主题注册
│   └── types.ts              # 主题类型
└── types/                    # 全局共享类型
    ├── common.ts             # 通用类型
    ├── front.ts              # 前台类型
    ├── result.ts             # 接口响应类型
    └── user.ts               # 用户类型
```

**职责边界**：
- 至少被两个业务模块复用才能放入
- 只有一个模块使用时，应放在模块内部
- 定期清理不再被多处使用的代码

### 3.3 `src/modules/` — 业务模块

每个模块内部自包含，保持高内聚低耦合。当前共有 **8 个业务模块**：

| 模块       | 路径                     | 功能描述                       |
| ---------- | ------------------------ | ------------------------------ |
| `home`     | `src/modules/home/`      | 首页门户（Hero、特性、统计等）  |
| `blog`     | `src/modules/blog/`      | 博客展示（文章列表、关于等）    |
| `admin`    | `src/modules/admin/`     | 管理后台（仪表盘、用户、角色等）|
| `ai`       | `src/modules/ai/`        | AI 对话（流式聊天、会话管理）   |
| `price`    | `src/modules/price/`     | 价格查询（趋势、区域、来源）    |
| `story`    | `src/modules/story/`     | 故事展示（图库、灯箱）          |
| `meditation` | `src/modules/meditation/` | 冥想功能（引导式冥想）        |
| `user`     | `src/modules/user/`      | 用户中心（个人资料、设置）      |

每个模块遵循统一内部结构：

```text
src/modules/<feature>/
├── pages/            # 页面组件（路由级组件）
├── components/       # 模块私有组件
├── api/              # API 接口层
├── store/            # Pinia 状态管理（可选）
├── composables/      # 组合式函数（业务逻辑）
├── constants/        # 模块常量
├── types/            # 模块类型定义
├── styles/           # 模块样式（可选）
└── index.ts          # 模块对外统一入口
```

### 3.4 `src/layouts/` — 布局骨架

```text
src/layouts/
├── FrontLayout.vue    # 前台门户布局（Header + 内容区 + Footer）
└── AdminLayout.vue    # 管理后台布局（侧边栏 + 顶栏 + 内容区）
```

### 3.5 `src/app/` — 应用入口

```text
src/app/
├── providers/
│   ├── index.ts       # 插件注册（Router、Pinia 等）
│   └── echarts.ts     # ECharts 全局注册
├── App.vue            # 根组件（仅 RouterView）
└── main.ts            # 入口文件（创建应用 + 挂载）
```

## 4. 数据流

```text
┌──────────────────────────────────────────────────┐
│               pages / components                  │
│            （展示层：只做展示与协调）                │
└──────────────────────┬───────────────────────────┘
                       │ 调用
                       ▼

└──────────────────────┬───────────────────────────┘
                       │ 调用
                       ▼

└──────────────────────┬───────────────────────────┘

                       ▼

                       │ HTTP
                       ▼
┌──────────────────────────────────────────────────┐
│                  后端 API                          │
└──────────────────────────────────────────────────┘
```

## 5. 路由架构

路由按门户（前台 / 管理后台）划分为两个独立模块，通过 Vue Router 全局守卫统一控制权限：

```text
src/core/router/
├── index.ts                 # 路由实例 + 全局守卫
│   ├── 合并 frontRoutes + adminRoutes
│   ├── beforeEach 守卫：
│   │   ├── 公开页面保护（已登录 → 自动跳转）
│   │   ├── 认证保护（未登录 → 拦截提示）
│   │   └── 角色保护（非管理员 → 跳转）
│   └── scrollBehavior 滚动行为控制
└── modules/
    ├── front.routes.ts      # 前台路由（home, blog, ai, story, meditation, price, user）
    └── admin.routes.ts      # 管理后台路由（dashboard, content, users, roles, features, etc.）
```

**路由元信息（meta）**：
- `requiresAuth`：需要登录认证
- `requiresAdmin`：需要管理员角色
- `publicOnly`：仅限未登录用户访问

## 6. 权限控制

权限系统位于 `src/core/permission/`，提供：

- `isAuthenticated()`：检查当前认证状态
- `getCurrentUser()`：获取当前用户信息
- `onAuthChange()`：监听认证状态变化

路由守卫中调用这些方法实现页面级权限控制。

## 7. 构建与开发配置

### 7.1 Vite 配置

```text
vite.config.ts
├── 插件
│   ├── @vitejs/plugin-vue       # Vue 单文件组件编译
│   ├── unplugin-auto-import     # Vue API 自动导入
│   └── unplugin-vue-components  # Element Plus 组件按需导入
├── 路径别名
│   └── @ → src/                 # 统一使用 @/ 别名导入
└── 开发服务器
    └── Proxy /api → localhost:8080
```

### 7.2 自动导入

- **Vue API**：`ref`、`computed`、`watch` 等无需手动 import
- **Element Plus 组件**：按需自动注册，无需手动导入
- 自动生成类型声明文件：`auto-imports.d.ts`、`components.d.ts`

## 8. 强制边界规则

| 规则                                        | 说明                                               |
| ------------------------------------------- | -------------------------------------------------- |
| 新增业务代码只在 `src/modules/<feature>/`    | 不允许在 core / shared / layouts 中新增业务代码     |
| `src/core/` 只放框架级能力                  | 不允许放业务代码、UI 组件、业务常量或类型            |
| `src/shared/` 只放被多处复用的代码           | 单一模块使用的代码放模块内部；定期清理冗余           |
| 页面只做展示与协调                          | 业务逻辑进入 composables / services / store         |
| 网络请求进入 `api/`                         | 不允许在组件中直接调用 Axios                         |
| 禁止新增全局按层目录                        | 不允许新增全局 `views/`、`components/`、`api/` 等   |
| 模块间禁止循环依赖                          | 共享数据通过 `src/shared/` 或 Pinia store 实现       |

## 9. 导入路径规范

```typescript
// ✅ 推荐：使用 @/ 别名 + 模块入口导入
import { PostsPage, useBlogList } from '@/modules/blog'
import { formatDate } from '@/shared/utils/formatDate'

// ✅ 允许：从模块具体路径导入
import { BlogCard } from '@/modules/blog/components/BlogCard.vue'

// ✅ 跨模块共享
import { useClipboard } from '@/shared/composables/useClipboard'

// ❌ 禁止：相对路径回溯
import { BlogCard } from '../../../components/BlogCard.vue'

// ❌ 禁止：模块间直接引用内部文件
import type { ArticleVO } from '@/modules/blog/types/article'
// → 改为从模块入口导入：import type { ArticleVO } from '@/modules/blog'
```

## 10. 命名规范

| 类型       | 命名方式                          | 示例                                  |
| ---------- | --------------------------------- | ------------------------------------- |
| 页面组件   | `{Name}Page.vue`                  | `HomePage.vue`、`PostsPage.vue`    |
| 普通组件   | `{PascalCase}.vue`                | `BlogCard.vue`、`PriceTrend.vue`      |
| Composable | `use{Noun}.ts`                    | `useBlogList.ts`、`useUserProfile.ts` |
| Store      | `{resource}.store.ts`             | `priceItem.store.ts`                  |
| API 文件   | 按资源命名                        | `article.ts`、`comment.ts`            |
| 类型文件   | 按资源命名                        | `article.ts`、`dto.ts`、`vo.ts`       |
| 目录       | `kebab-case`                      | `price/`、`blog/`、`user/`            |

## 11. 样式体系

- **SCSS** 作为预处理器，保持 `scoped` 和 BEM 风格
- 使用 `src/shared/styles/_tokens.scss` 设计令牌，禁止硬编码颜色值
- 主题系统支持多套皮肤切换（Apple 风格、Element 默认风格等）
- 全局样式统一由 `src/shared/styles/index.scss` 入口引入

## 12. 目录深度约束

| 约束         | 值             | 说明                               |
| ------------ | -------------- | ---------------------------------- |
| 最大目录深度 | 4～6 层         | 超过则重新拆分模块                  |
| 同级最大子项 | 15～20 个       | 超过则分子目录                      |
| 核心原则     | 横向跳转最小化 | 开发一个功能时尽量在对应模块内完成  |
