# Kite 项目架构说明

> 本文档用于快速理解项目当前的整体结构、目录职责和分层关系，供架构梳理、对外介绍以及后续重新设计架构时参考。本文只讲“代码大概放在哪里、各自负责什么”，不逐文件展开。

## 1. 项目定位

Kite 是一个基于 Vue 3 + TypeScript + Vite 的个人网站与内容平台，采用前台站点与后台管理双门户结构，业务能力按域组织，强调模块化扩展和前后端联调。

## 2. 顶层目录

| 目录/文件                                                          | 职责                  |
| ------------------------------------------------------------------ | --------------------- |
| `src/`                                                             | 全部应用源码          |
| `public/`                                                          | 不参与构建的静态文件  |
| `dist/`                                                            | 生产构建产物          |
| `.docs/`                                                           | 项目文档与规范        |
| `.claude/`                                                         | AI 协作技能与设计参考 |
| `package.json` / `vite.config.ts` / `tsconfig.json` / `index.html` | 工程配置与入口        |

## 3. `src/` 目录职责

| 目录           | 职责                                                         |
| -------------- | ------------------------------------------------------------ |
| `api/`         | 网络请求层：axios 实例、拦截器，以及按业务域拆分的接口模块   |
| `assets/`      | 静态资源，按前端展示、业务模块、状态图等场景分组             |
| `components/`  | 组件层，按功能域分组：站点、AI、博客、后台面板、价格等       |
| `composables/` | 组合式函数；部分逻辑已迁移到 Pinia，保留为参考               |
| `config/`      | 应用配置、模块注册中心、自动生成类型声明                     |
| `constant/`    | 常量与纯静态配置，按业务域拆分                               |
| `layouts/`     | 门户布局骨架：前台布局与后台布局                             |
| `router/`      | 路由表与路由守卫，前台/后台分开维护                          |
| `stores/`      | Pinia 状态管理，按业务域拆分                                 |
| `style/`       | SCSS 设计系统：设计令牌、基础样式、工具类、Element Plus 主题 |
| `types/`       | TypeScript 类型定义，按业务域拆分并统一导出                  |
| `utils/`       | 跨模块工具，如认证与登录态管理                               |
| `views/`       | 页面级视图，前台/后台分目录                                  |

## 4. 分层与数据流

页面与组件不直接拼接后端 URL，请求统一走接口层：

```text
views / components
        ↓
stores / composables
        ↓
api/modules
        ↓
axios 请求层
        ↓
后端接口
```

对应的代码归属：

- 业务接口放在 `api/modules/`
- 请求/响应类型放在 `types/modules/`
- 常量与静态配置放在 `constant/modules/`
- 页面放在 `views/`
- 页面复用的组件放在 `components/`

## 5. 双门户结构

- 前台门户：`/` 下的公开与个人页面，包含首页、价格、AI 对话、博客、个人中心等。
- 后台门户：`/admin` 下的管理页面，包含控制台、内容管理、用户/角色、焦点项目、特性管理等。
- 路由守卫根据登录态与 `ADMIN` 角色控制访问范围。

## 6. 模块扩展方式

新增业务模块时，按现有约定补齐以下部分：

1. 在 `config/modules/` 增加模块配置并注册
2. 在 `api/modules/` 增加接口
3. 在 `types/modules/` 增加类型
4. 在 `constant/modules/` 增加常量
5. 在 `components/` 与 `views/` 增加页面和组件
