# 网站风格与设计方向

> 本文是风格调研与方向建议，供后续 UI 规范化时参考，不构成最终强制规范。

## 1. 主流网站风格

| 风格 | 特点 | 适合 |
| --- | --- | --- |
| Material Design | 卡片、阴影、层级明显 | 企业后台、管理系统 |
| Fluent Design | 微软风格、透明、亚克力 | Windows 应用、办公系统 |
| Apple Human Interface | 留白多、圆角、大字体 | 官网、个人网站 |
| Ant Design | 企业级、中后台 | SaaS、ERP、CRM |
| Semi Design | 字节风格 | 内容平台、AI 平台 |
| Naive UI 风格 | 极简 | Vue 项目 |
| Glassmorphism | 毛玻璃 | AI 产品、作品集 |
| Neumorphism | 浮雕 | Demo、展示 |
| Bento Grid | 模块化卡片 | AI、博客、个人主页 |
| Dashboard Style | 数据面板 | 后台系统 |

## 2. 个人网站方向

Kite 适合采用 **Apple + Bento + Glass**：

- Apple Human Interface：留白、大标题、柔和颜色、自然动画。
- Bento Grid：首页以模块化卡片为核心，突出 AI、博客、项目等内容。
- Glassmorphism：轻量毛玻璃质感，适合 AI 产品和作品集。

首页参考形态：

```text
┌───────────────┐
│ Hero          │
├─────┬─────────┤
│Blog │ AI      │
├─────┼─────────┤
│Git  │ Project │
└─────┴─────────┘
```

参考产品：OpenAI、Anthropic、Linear、Vercel、Arc。

## 3. 后台管理风格

| 类型 | 特点 | 代表 |
| --- | --- | --- |
| 传统 Admin | 左菜单 + 顶部 Header + 右侧内容 | SpringBoot Admin、Ruoyi、Element Admin |
| Dashboard | 数据入口，统计/图表/趋势/日志 | GitHub、Grafana、Kibana、Datadog |
| Notion 风格 | 去复杂 Header/Menu，页面即内容 | Notion、Outline、Affine、AppFlowy |
| Linear 风格 | 超干净，灰白黑 + 少量强调色，按钮极少 | Linear、Raycast、Vercel、Cursor |
| AI Dashboard | Workspace/Project/Model/Prompt 等卡片化工作区 | ChatGPT、Claude、Perplexity、Lovable、Bolt |

## 4. 后台布局

| 布局 | 结构 | 适用 |
| --- | --- | --- |
| Sidebar | Logo + 菜单 + 内容 | 经典后台 |
| Top Navigation | 顶部菜单 + 下方内容 | 官网，不适合复杂后台 |
| Sidebar + TopBar | Header + Sidebar + Content | 企业后台，推荐 |
| Workspace | Sidebar + Explorer + Content + Inspector | Cursor、Figma、Notion |

推荐 Kite 后台采用 **Sidebar + TopBar**：

- 左侧导航。
- 顶部工具栏。
- 右侧工作区。

## 7. Kite 设计方向

### 前台

- Apple Human Interface + Bento Grid + Glassmorphism。
- 首页以模块卡片为核心，突出 AI、博客、项目。
- 视觉接近 OpenAI、Vercel、Linear。

### 后台

- Linear 风格 + Ant Design 的信息组织方式。
- 布局使用 Sidebar + TopBar。
- 配色以白、灰为主，仅使用一种强调色（蓝色或紫色）。
- 避免传统 Ruoyi 式后台模板的陈旧感。

### Dashboard

- 参考 Grafana 或 GitHub 仪表盘。
- 首页以统计卡片、趋势图、最近活动为主，而不是菜单入口。

## 8. 落地原则

- 统一使用设计令牌，控制颜色、圆角、阴影、间距。
- 后台只保留一种强调色，减少视觉噪音。
- 前台保留品牌叙事型手写 UI，通用交互组件使用 Element Plus。
- 后续 UI 规范以本文和 `UI实现现状与规范.md` 为共同依据。
