# Kite 项目架构说明

> 本文档用于快速理解项目当前的整体结构、目录职责和分层关系，供架构梳理、对外介绍以及后续重新设计架构时参考。本文只讲“代码大概放在哪里、各自负责什么”，不逐文件展开。

## 1. 项目定位

Kite 是一个基于 Vue 3 + TypeScript + Vite 的个人网站与内容平台，采用前台站点与后台管理双门户结构，业务能力按域组织，强调模块化扩展和前后端联调。

## 2. 顶层目录

| 目录/文件                                                          | 职责                  |
| ------------------------------------------------------------------ | --------------------- |
| `src/`                                                             | 全部应用源码          |
| `public/`                                                          | 不参与构建的静态文件  |
| `dist/`                                                            | 生产构建产物          |
| `.docs/`                                                           | 项目文档与规范        |
| `package.json` / `vite.config.ts` / `tsconfig.json` / `index.html` | 工程配置与入口        |

## 3. `src/` 目录职责

| 目录           | 职责                                                         |
| -------------- | ------------------------------------------------------------ |
| `app/`         | 应用入口与 providers 初始化                                   |
| `core/`        | 框架层：API 请求实例、路由、权限、配置与自动生成类型声明     |
| `shared/`      | 跨业务复用的组件、常量、类型、静态资源与样式                 |
| `modules/`     | 业务模块，按 Feature 自包含 pages/components/api/store/...  |
| `layouts/`     | 门户布局骨架：前台布局与后台布局                             |

## 4. 分层与数据流

页面与组件不直接拼接后端 URL，请求统一走接口层：

```text
modules/<feature>/pages + components
        ↓
modules/<feature>/composables + store
        ↓
modules/<feature>/api
        ↓
core/api/request
        ↓
后端接口
```

对应的代码归属：

- 业务接口放在 `modules/<feature>/api/`
- 请求/响应类型放在 `modules/<feature>/types/`
- 常量与静态配置放在 `modules/<feature>/constants/`
- 页面放在 `modules/<feature>/pages/`
- 模块内组件放在 `modules/<feature>/components/`
- 两个及以上模块复用的代码放在 `shared/`

## 5. 双门户结构

- 前台门户：`/` 下的公开与个人页面，包含首页、价格、AI 对话、博客、个人中心等。
- 后台门户：`/admin` 下的管理页面，包含控制台、内容管理、用户/角色、焦点项目、特性管理等。
- 路由守卫根据登录态与 `ADMIN` 角色控制访问范围。

## 6. 模块扩展方式

新增业务模块时，按现有约定补齐以下部分：

1. 在 `core/config/modules/` 增加模块配置并注册
2. 在 `modules/<feature>/api/` 增加接口
3. 在 `modules/<feature>/types/` 增加类型
4. 在 `modules/<feature>/constants/` 增加常量
5. 在 `modules/<feature>/pages/` 与 `components/` 增加页面和组件
6. 跨模块复用的代码放入 `shared/`，框架能力放入 `core/`
