# Kite 项目架构说明

> 本文档描述 **Feature-first（Hybrid）重构之后** 的 Kite 项目结构，帮助理解“破坏性重构”后的代码归属、数据流和扩展方式。

## 1. 项目定位

Kite 是一个基于 Vue 3 + TypeScript + Vite 的个人网站与内容平台，采用前台站点 + 后台管理双门户结构，业务能力按域组织，强调模块化扩展和前后端联调。

## 2. 重构目标与成果

- 删除旧的全局限层目录：`views/`、`components/`、`api/`、`types/`、`constant/`、`config/`、`router/`、`stores/`、`composables/`、`utils/`。
- 业务代码全部收进 `src/modules/<feature>/`，一个业务模块自包含页面、组件、API、类型、常量、composable、store。
- 框架能力集中在 `src/core/`，跨业务复用集中在 `src/shared/`。
- 登录接口和认证 DTO 归入 `src/modules/user/`，与后端用户中心设计一致。
- Pitaya 电商模块已取消开发，前端代码已删除。
- 不再保留旧架构兼容 shim。

## 3. 顶层结构

| 目录/文件 | 职责 |
| --- | --- |
| `src/` | 全部应用源码 |
| `public/` | 不参与构建的静态文件 |
| `dist/` | 生产构建产物 |
| `.docs/` | 项目文档与规范 |
| `package.json` / `vite.config.ts` / `tsconfig.json` / `index.html` | 工程配置与入口 |

## 5. 各层职责

### `app/`

负责应用启动：

- 创建 Vue 实例。
- 统一注册 Pinia、Router、Element Plus。
- 初始化 ECharts 与地图。
- 挂载 `#app`。

### `core/`

只放框架级能力：

- API 请求实例与拦截器。
- 路由表与路由守卫。
- 登录态存取与权限判断。
- 应用配置、模块注册中心、自动生成类型声明。

### `shared/`

只放被两个及以上业务模块复用的代码：

- 共享组件。
- 共享常量。
- 共享类型。
- 全局样式。
- 静态资源。

### `modules/`

每个业务模块自包含：

```text
modules/<feature>/
├── pages/
├── components/
├── api/
├── store/
├── composables/
├── constants/
├── types/
├── services/
└── index.ts
```

### `layouts/`

门户布局骨架：

- `FrontLayout.vue`：前台头部、菜单、登录弹窗、页脚。
- `AdminLayout.vue`：后台最外层容器。

## 6. 业务模块清单

| 模块 | 门户 | 主要职责 |
| --- | --- | --- |
| `home` | 前台 | 首页、Hero、特性、统计、CTA |
| `story` | 前台 | 画廊与灯箱 |
| `blog` | 前台 | 博客、文章列表、教育、技能 |
| `user` | 前台 | 登录认证、个人中心、公开资料、账户 |
| `ai` | 前台 | AI 对话、会话管理、流式输出 |
| `price` | 前台 | 物品查询、价格趋势、地区/来源对比 |
| `meditation` | 前台 | 冥想内容与播放引导 |
| `admin` | 后台 | 控制台、用户/角色/焦点/特性管理 |

模块注册中心位于 `src/core/config/modules.ts`，新增模块需要在该注册表中登记。

## 7. 数据流

页面与组件不直接拼接后端 URL，请求统一走接口层：

```text
modules/<feature>/pages + components
        ↓
modules/<feature>/composables + store
        ↓
modules/<feature>/api
        ↓
core/api/request
        ↓
后端接口
```

对应的代码归属：

- 业务接口放在 `modules/<feature>/api/`。
- 请求/响应类型放在 `modules/<feature>/types/`。
- 常量与静态配置放在 `modules/<feature>/constants/`。
- 页面放在 `modules/<feature>/pages/`。
- 模块内组件放在 `modules/<feature>/components/`。
- 两个及以上模块复用的代码放在 `shared/`。

## 8. 核心机制

### API 层

- `core/api/axios.ts`：创建 Axios 实例，`baseURL=/api`，10 秒超时。
- `core/api/interceptor.ts`：请求注入 Bearer Token，响应统一解包 `Result<T>`，登录态失效自动清理。
- `core/api/request.ts`：默认导出请求实例，并导出 `ApiError`。

### 路由

- `core/router/index.ts`：创建 Router，挂载前台/后台路由。
- 前台路由前缀 `/`。
- 后台路由前缀 `/admin`，侧边栏一个菜单项对应一个模块页面。
- 当前后台路由暂未启用登录/管理员守卫，方便通过路径直接预览后台界面；后续可按需恢复。

### 认证

- `core/permission/auth.ts`：基于 localStorage + CustomEvent 管理登录态。
- 登录、验证码、重置密码接口位于 `modules/user/api/auth.ts`。
- 认证 DTO 位于 `modules/user/types/auth.ts`。
- `core/permission` 与 `modules/user` 之间是当前唯一的 core → module 依赖，属于认证横切能力。

### 状态管理

- Pinia 已接入。
- 当前业务 store 示例：`modules/price/store/priceItem.store.ts`。
- 后续新增业务状态放在对应模块的 `store/`。

### 自动导入

- unplugin-auto-import 与 unplugin-vue-components 自动生成：
  - 根目录 `auto-imports.d.ts`
  - 根目录 `components.d.ts`
- Vite 组件扫描目录包含 `src/modules` 与 `src/shared/components`。

## 9. 前台与后台

### 前台

- 首页、画廊、博客、AI 对话、价格行情、冥想、个人中心。
- 品牌/叙事型 UI 以手写 SCSS 为主，统一使用设计令牌。

### 后台

- 布局：`el-container` + `el-aside` + `el-header` + `el-main`。
- 侧边栏：`el-menu`，一个菜单项对应一个模块。
- 内容页：控制台、内容管理、用户、角色、焦点、特性、设置。
- UI 风格：Linear 风格，全面使用 Element Plus 组件，主题覆盖集中在 `shared/styles/_element-plus.scss`。

## 11. 构建与工程

- `vite.config.ts`：Vue 插件、unplugin 自动导入、`@/` 别名、`/api` 代理。
- `tsconfig.json`：继承 `@vue/tsconfig`，包含自动生成类型声明。
- 开发代理：`/api` → `VITE_API_BASE_URL`，缺省 `http://127.0.0.1:18080`。

```bash
npm run dev          # 启动 Vite 开发服务器
npm run type-check   # TypeScript 类型检查
npm run build        # 类型检查 + 生产构建
npm run preview      # 预览生产构建
```

## 12. 新增业务模块步骤

1. 在 `src/modules/<feature>/` 创建模块目录。
2. 按模块结构补齐 `pages/`、`components/`、`api/`、`types/`、`constants/` 等。
3. 创建模块 `index.ts` 统一导出。
4. 在 `src/core/config/modules.ts` 注册模块配置。
5. 在 `src/core/router/modules/` 接入页面路由。
6. 跨模块复用的代码放入 `shared/`，框架能力放入 `core/`。
7. 执行 `npm run type-check` 与 `npm run build`。

## 13. 重构状态与已知事项

- 旧按层目录已全部删除。
- 登录接口归属 `modules/user`。
- Pitaya 模块已取消开发。
- 后台路由当前开放预览，未启用管理员守卫。
- 个人中心公开资料表单仍是原生表单，后续计划改为 Element Plus。
- AI 聊天、全屏菜单、画廊灯箱等品牌型 UI 暂保留手写实现。
